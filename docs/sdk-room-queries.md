## 并发与失败行为

- 启动核心注册成功后自动查询；每次连接重新注册后全部重新初始化，start不等待查询。
- 单类查询仅保留一个在途请求，并发调用返回该请求future的独立副本，不开放任意发送接口。
- 保留目标UID、连接ID、请求ID、请求/接收时间、结果状态和响应哈希。HTTP请求ID由客户端生成，WUP请求ID与响应header关联。
- WUP响应还校验函数名；旧连接、已超时或已取消请求的迟到响应不能覆盖缓存。
- 断连和关闭结束所有在途请求，缓存清为未知；不会把上个连接的成功数据默认为当前数据。
- 3102、6249按当前连接及目标身份/分组更新缓存。已在途查询的结果不能覆盖请求发起之后收到的较新推送。
- 查询超时和HTTP/响应错误只影响查询结果，不为了查询失败重连实时连接；future用户续接任务不在控制线程完成。
- 零值、字段缺失、失败分别表示；HTTP重复键、尾随内容、错误返回码、负数、溢出和压缩解码尺寸均有检查。
- 直播状态查询缓存由查询刷新，实时开/下播继续使用既有Live事件；后端按场次ID决定是否通知，SDK不执行通知去重。

## 验证范围

新增7项本地测试覆盖：真实0/未知/身份不符；直播/回放/场次与时间；完整目录及大整数ID；HTTP格式/溢出/压缩；启动和主动刷新；守护推送替换及外房间拒绝；查询超时不重连、关闭完成请求；重连迟到HTTP隔离；用户future阻塞不影响保活；较新推送不被迟到查询覆盖。

完整构建覆盖SDK、旧Demo和持续采集Demo。这些接口自0.1.1提供，0.1.0保持原样且不包含新接口。公共协议可能变化；查询失败及接收缺口不能视作0或未播，短时验证也不保证未来平台消息完整。
